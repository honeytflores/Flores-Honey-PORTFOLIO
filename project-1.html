PROJECT 01 · PERSONAL DATA ANALYSIS PROJECT

Transaction Fraud Detection

Using transaction patterns to explore how data preparation and machine learning can help identify potentially fraudulent activity.

Project type: Personal project · Tools used: SQL, Python, Random Forest

8,000 TRANSACTIONS · 0.75 ROC-AUC ON HELD-OUT DATA

PERSONAL PROJECT · NOT A PRODUCTION FRAUD-DETECTION SYSTEM

Scenario

Could patterns in a dataset of 8,000 transactions help distinguish potentially fraudulent activity from legitimate transactions? This personal project explores that question as a modeling exercise, not as a deployed or production system.

Summary

I prepared and structured the transaction records with SQL, then trained a Random Forest classifier in Python. The model achieved a 0.75 ROC-AUC on held-out transactions. The result is a useful baseline for a personal project, with further feature engineering needed to improve it.

Key Challenges and Solutions

Preparing records for modeling

The transaction data needed a consistent structure before model training. I used SQL to clean and prepare the 8,000 records first.

Evaluating the result realistically

Rather than presenting the model as production-ready, I evaluated it on held-out transactions, reported its 0.75 ROC-AUC, and noted the need for further feature engineering.

What I Learned

The project helped me practice an end-to-end workflow—from data preparation through model evaluation—and reinforced that a model score needs context. A 0.75 ROC-AUC is a starting point to investigate and improve, not proof that a fraud model is ready for real-world decisions.

Why it Matters

Fraud analysis can affect both customers and business decisions, so useful detection work needs careful data preparation and honest evaluation. This project connects my prior experience reviewing disputes with the technical skills I’m building, while keeping clear that this model was a personal exercise—not a deployed system or a replacement for human review.
